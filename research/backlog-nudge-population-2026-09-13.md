# AF-770: one population for native backlog nudges

MSG-59977 from ts-gke reported repeated rechecks of parked cards. GET-only readback of the seven exact cards and 40 recent messages on stable build 92574406b0d20987 separated two mechanisms:
- Native pickup MSG-59704 promises a 24-hour trigger exclusion, says five drainable cards, but lists only TG-3705.
- Session messages MSG-59973/59932/59839 originate from mixpeek-orchestrator and list the parked TG cards. Their own movement/backoff promise is a separate generator, retained as AF-771 for its owner. Fixing native selection does not establish that tick is fixed.

Native backlog_candidates excluded blocked_on. The inline count used for the idle-drain decision, cadence and escalation did not. The old AF-516 test exercised the list and automatic pickup but never that third query. Extracting the unchanged actual counter and adding a blocked-only assertion failed deterministically: counted 1, expected 0; 0 passed / 1 failed. Parent specimen is 3c174603; the saved red-specimen patch adds only that extraction and assertion.

The nudge now reads one complete eligible population and derives its denominator and first-eight display from those same operands. Dispatch eligibility is shared: blocked_on, fresh triggers, needs:you, dormant types, parked captures, recent claims and unresolved dependencies all remain exclusions. An expired trigger without another blocker can return; trigger expiry does not remove blocked_on. More than eight eligible cards produce an explicit remaining count in the prompt. Stale-backlog triage is still a separate mechanism and is not changed to silently suppress old parked work.

The shared selector returns actual database errors instead of flattening unreadable rows into absence. The nudge refuses an unreadable population and logs backlog_nudge_population_unmeasured with measured=false and why_unmeasured. Successful nonempty backlog reads log backlog_nudge_population with measured=true, n_considered, eligible, excluded and listed. Delivered event records also carry counts. Dependency lookup errors remain conservatively blocking with their existing dependency_resolution_unmeasured signal; this change does not certify those dependencies as measured-ready.

Coverage includes the original blocked-only reproduction, a 21-card eligibility matrix with 13 eligible and an 8+5 display split, and real captured tracing output for mixed selection and missing-schema/tag-table errors. Author `scripts/safe-cargo.sh test -p amux-server --lib runtime_jobs::board_drive:: -- --test-threads=4` passed 173 tests, 0 failed. Clean snapshot gates, independent review and live adoption are still required before closure. No TG card was edited, no trigger was refreshed on someone else's behalf, and no orchestrator source was changed.
